## 2026-09-12

### Added
- `code/R/15_04_tumor_trajectory_working.R`: New GAM spec **`pseudobulk_nb`** — a proper **negative-binomial GAM on summed raw counts** at the pseudobulk (sample×bin) level, added to the default `GAM_MODELS` and `FULL_GENE_MODELS`. This is the pseudobulk analog of the `15_07` tradeSeq cell-level NB-GAM and implements the previously **deferred reviewer point #3-B** (mean-of-log-normalized pseudobulk is biased vs summing raw counts + NB with a library-size offset). It reuses the `pseudobulk_rs` between-mouse random structure — random intercept `s(sample,bs="re")` + random linear slope `s(score,sample,bs="re")`, `select=RS_SELECT` + `gamma=RS_GAMMA` so the ordered-factor difference smooth can shrink to zero — but fits `family=nb()` on per-gene **summed counts** with a `log(library-size)` **offset** and **no `n_cells` weights** (the offset carries sequencing depth, incl. the systematically higher DKO library size — reviewer #3-D). Implementation: `make_pseudobulk()` gains an `agg=c("mean","sum")` argument (sum → raw counts per gene + a `libsize` = group total counts for the offset); the per-model loop builds the NB pseudobulk from the raw `counts_ct` matrix (`agg="sum"`) while the Gaussian specs keep averaging the log-normalized data layer; `fit_trajectory_gam()` gets a new branch (NB formula with `offset(log_libsize)`, `family=nb()`, both random terms excluded from the population-curve prediction, offset held at its mean depth so the fitted curve is on the log-E[count] scale); `df_gam` carries `log_libsize=log(pmax(libsize,1))`; the per-gene spline plot puts observed counts on the same depth-adjusted log scale (`log(count+0.5)-log_libsize+mean(log_libsize)`) so points overlay the NB curve, with a matching y-axis label. The condition test (`p_shape`/`p_level`, now on the log link), BH-FDR CSV, significant-trajectory heatmap, and (optional) per-gene PDFs all flow through unchanged — the existing `^Pr(` p-value-column grep (reviewer #3-C) already handles the NB `Pr(>|z|)` column. New `PSEUDOBULK_NB_MODELS` vector marks specs needing the summed-counts/offset build; `stopifnot` and the model-set checks updated. Functionally verified on synthetic pseudobulk (converges, correct `Pr(>|z|)` extraction, offset+RE-excluded prediction). Note this is still a cell-level→sample×bin aggregation at n=3 WT/4 DKO, so — like every spec here — its per-gene shape p-values remain bounded by the sample-level permutation floor documented in `notes.md`; the NB refactor removes the mean-of-log bias, it does not change the honest inference regime.
- `code/R/15_07_tumor_trajectory_tradeseq.R`: New **tradeSeq** (Van den Berge et al. 2020) NB-GAM cross-check of the tumor-proximity trajectory for CD8+ T, added as the citable orthogonal method flagged in `trajectory.md` (and to bring a proper negative-binomial + library-size-offset likelihood on raw counts, the deferred reviewer point #3-A). Runs on the **identical diffusion local-tumor-fraction score** used by `15_04` (same `compute_tumor_score()` diffusion/heat settings: `heat_steps=20`, `alpha=2`, `k=30`, `local_fraction=TRUE`, `normalize=FALSE`), so the two analyses share one x-axis — same axis, different statistical engine. Fits per-gene condition-specific NB-GAMs via `fitGAM()` (single spatial "lineage" = the score as pseudotime, `cellWeights=1`, `conditions=WT/DKO`, `nknots=6`, parallelized over genes with `BiocParallel::MulticoreParam`) on the same DE-consistent expression-filtered gene set as `15_04` (`00_parameters.R` filters). Reports `associationTest()` (varies along the gradient) and `conditionTest()` (WT-vs-DKO smoother difference — the `p_shape` analog) as BH-FDR CSVs, per-gene `plotSmoothers()` PDFs for the top conditionTest genes, a WT|DKO fitted-smoother ComplexHeatmap (shared per-gene z-score, matching the `15_04` significant-trajectory aesthetic), and the WT-vs-DKO density-along-gradient plot; saves the fitted SCE. **Framing (baked into the header, CSVs, and figure titles):** tradeSeq's conditionTest is a **cell-level** test with **no biological-replicate random effect** and **no common-support filter**, so at n=3 WT / 4 DKO it is the anticonservative pseudoreplication regime `notes.md` diagnosed — results are an **EXPLORATORY ranking, not honest inference**, expected to flag far more genes than the defensible `pseudobulk_fs` spec (that inflation is the artifact, not biology). Optional `evaluateK()` knot diagnostic behind `RUN_EVALUATEK`. Dependency guard errors with `BiocManager::install('tradeSeq')` instructions if the package is absent (not installed in-env by default). Outputs to `output/R/15_tumor_trajectory_tradeseq/`.

## 2026-09-10

### Added
- `code/R/15_04_tumor_trajectory_working.R`: New GAM spec **`pseudobulk_rs`** (random intercept + random slope), added alongside `pseudobulk` and `pseudobulk_fs` in the default `GAM_MODELS` (and `FULL_GENE_MODELS`) so the three run side-by-side, each producing its own `gam_condition_test_<model>.csv` + significant-trajectory heatmap. Responds to reviewer feedback that the per-sample factor smooth `s(score,sample,bs="fs")` is over-parameterized at 7 samples / ~9 pseudobulk points per mouse (the source of the row-order instability that forced the `FS_K<-3` clamp). `pseudobulk_rs` replaces the per-sample penalized curve with two variance components — `s(sample,bs="re")` (random intercept) + `s(score,sample,bs="re")` (random linear slope) — which is well-conditioned with no basis to saturate, hence order-stable by construction and needing **no** `FS_K`. It still holds between-mouse level + linear-trend heterogeneity in the error term (only unidentifiable non-linear per-mouse shape is given up). Fit with `select=TRUE` (Marra & Wood 2011 double penalty, so the ordered-factor difference smooth can shrink to exactly zero — removes the unpenalized-linear boundary that makes the by-smooth p-value anticonservative) and `gamma=1.4` (biases toward smoother fits), both exposed as toggleable params `RS_SELECT`/`RS_GAMMA`. Wired through `fit_trajectory_gam()` (new branch, both random terms excluded from the population-curve prediction, `select`/`gamma` now passed to `gam()` and defaulting to `FALSE`/`1` for the other specs so their behavior is unchanged), a shared `PSEUDOBULK_MODELS` vector replacing the hard-coded `c("pseudobulk","pseudobulk_fs")` model-set checks, the parameter report, and the `stopifnot` validation. Functionally verified: fit converges, difference-smooth p extracts, two-term `exclude` prediction works.
- `code/R/15_04_tumor_trajectory_working.R`: Writes a **run-parameter report** into `OUTPUT_DIR` as the first action after parameter validation — before the 3.5 GB `readRDS`, tumor scoring, and GAM fits — so every result folder is self-documenting and an interrupted/crashed run still records exactly which settings were used. New `write_param_report()` emits both `run_parameters.csv` (group, parameter, value) and a human-readable `run_parameters.txt`, capturing all switchable parameters grouped as run/tumor_score/binning_support/genes/gam_models/condition_test_viz/qc/design, plus provenance (timestamp, host, R + mgcv/Seurat/ComplexHeatmap versions, thread count, input RDS) and the DE-consistent gene-filter thresholds pulled from `00_parameters.R`.
- `code/R/16_04_loso_influence.R`: New leave-one-sample-out (LOSO) influence diagnostic for the trajectory shape test, complementing the sample-label permutation (`16_03`). Reuses 16_03's exact stable-config machinery (local-fraction score, `pseudobulk_fs` with `GAM_K=5`/`FS_K=3`, common support, real-score axis) but instead of permuting labels it drops each mouse in turn — keeping the true WT/DKO labels — recomputes binning + common support on the remaining 6 mice, and refits all baseline-filtered genes. Reports, per gene, the full-fit FDR and the FDR under each of the 7 drops, a "significant in k/7 subsets" robustness count, and which single mouse's removal breaks each full-fit-significant gene; plus a per-dropped-sample significant-gene-count bar and an influence heatmap. Directly answers "does one sample drive the findings?" — orthogonal to the 1/35 permutation floor. Header documents why a cell-position/score-shuffle null was considered and rejected (it moves the exchangeable unit back to the cell → reintroduces pseudoreplication and tests the wrong null). Outputs to `output/R/16_loso_influence/`.

### Added
- `code/R/15_04_tumor_trajectory_working.R`: New GAM spec **`pseudobulk_fs`** (selectable via `GAM_MODELS`), added in response to reviewer feedback that the random-*intercept* specs (`pseudobulk`/`ranef`, `s(sample, bs="re")`) cannot legitimately test `p_shape` — they absorb per-sample *level* but not per-sample *curve shape*, so the by-condition difference smooth is tested against ~140 pseudobulk-bin residuals rather than the 7 mice, attributing between-mouse trajectory-shape heterogeneity to condition (anticonservative). `pseudobulk_fs` fits the pseudobulk (sample×bin, `n_cells`-weighted) data with a factor-**smooth** random effect `s(score, sample, bs="fs")` giving each sample its own penalized curve (random intercept **and** shape); the fs term subsumes the intercept so no separate `re` term. This is the defensible spec for the trajectory-shape question. Wired through `fit_trajectory_gam()` (new branch, `excl="s(score,sample)"`, `weights=n_cells`), the pseudobulk-data build, the per-gene GAM plots, and the significant-trajectory heatmap (all now `model %in% c("pseudobulk","pseudobulk_fs")`-aware). Default `GAM_MODELS <- c("pseudobulk", "pseudobulk_fs")`, `FULL_GENE_MODELS` includes it. **Result (CD8+ T, top-40 variance genes):** shape hits at BH-FDR<0.1 drop from **27** (`pseudobulk`: Prf1, Gzmb, Fasl, Cd274, Irf1, Pdcd1, Ifng, …) to **0** (`pseudobulk_fs`; strongest Ccl3 `fdr_shape`=0.14, Prf1=0.31) — i.e. no defensible per-gene trajectory-*shape* difference survives correct sample-level error at n=3 WT vs 4 DKO. The `p_level` (between-mouse level) test is robust across specs (5 genes — Mki67, Cd8a, Thy1, Cd3e, Ccl5 — significant in both), confirming `p_level` ≈ the trustworthy bulk-DE-like quantity. Evaluation + numbers recorded in `notes.md` (reviewer point #2).
- `code/R/16_02_small_diagnostics.R`: New quick sanity-check script that tests whether the 15_04 tumor-proximity axis is **confounded with condition** — i.e. whether a WT-vs-DKO `p_shape` difference could be an artifact of axis construction rather than biological gradient remodeling. Runs three checks on the real cohort using the **same scoring parameters as 15_04** (diffusion/heat, k=30, heat_steps=20): **(1) graph bandwidth** `sigma` = median k-NN distance per sample (the Gaussian kernel width in `score_diffusion()`, and a direct proxy for local cell density); **(2) RAW pre-normalization tumor field** via `compute_tumor_score(..., normalize = FALSE)` (per-sample mean/median/max/range, since 15_04's per-sample [0,1] rescale erases absolute magnitude); **(3) tumor fraction** per sample. Tabulated per-sample and per-condition (WT vs DKO means, ranges, ratio, underpowered wilcox p at n=3v4). **Finding — the axis geometry is NOT confounded:** `sigma` is essentially identical across conditions (WT 24.3 vs DKO 23.5, ratio 0.96, ranges fully overlapping, p=1.0), so the diffusion length scale — "one step along the axis" — means the same physical distance in WT and DKO, the property `p_shape` requires. Tumor fraction / raw-field mean trend ~2× higher in WT (0.22 vs 0.10) but this is **within-condition heterogeneity, not a clean split** (DKO2 = 0.32 is WT-like; DKO1/DKO3 = 0.01/0.03 are tumor-sparse; ranges overlap, p≈0.23–0.40); note `raw_field_mean ≈ tumor_frac` because the symmetric-normalized heat kernel ~conserves the source mean. Interpretation: `p_shape` is not mechanically invalidated, but the deep-tumor end of the trajectory is thin in the two tumor-sparse DKO samples (same sparse-bin issue as WT3, now confirmed tumor-abundance-driven and partially condition-correlated) — a power/balance caveat to state in the methods, not an artifact. Outputs `diagnostics_by_sample.csv`, `diagnostics_by_condition.csv`, `diagnostics_by_condition.png` to `output/R/16_small_diagnostics/`.
- `code/R/14_04_diffusion_optimization.R`: New standalone hyperparameter grid-search script (based on `15_04` + `00_utils.R`) to help choose the heat-diffusion tumor-score strength. Sweeps `ALPHA_GRID` × `HEATSTEP_GRID` (both user-editable at the top; total diffusion time `T = heat_steps × alpha` sets the spatial length scale), rebuilding the per-sample tumor-proximity score field for every combination and plotting it as a spatial scatter. Efficiency: the Gaussian-weighted spatial k-NN graph depends only on coords+`k`, so it is built **once per sample** and reused across the whole grid; only the cheap `.diffuse_field()` solve repeats per grid cell. Diffusion always uses all cells; plotting subsamples to `N_PLOT_CELLS` (default 20000). **PNG-only outputs** to `output/R/14_diffusion_optimization/`: one `diffusion_grid_<sample>.png` per sample (alpha rows × heat_steps cols facet grid) plus `diffusion_grid_ALL_stacked.png` (all samples stacked vertically). Header documents the theory (unconditional stability for any `alpha>0`; over-smoothing limit as `T→∞` collapses to the flat stationary/degree distribution; tune to field/distribution shape and apply globally, never to a downstream p-value count).

- `code/R/15_04_tumor_trajectory_working.R`: Replaced the condition test in `fit_trajectory_gam()`. The old approach compared two penalized GAMs via `anova(null_ml, full_ml, test="Chisq")` (ML refit), which returned `NA` for ~15% of genes — diagnosis showed this is the well-known unreliability of deviance-based LRTs on penalized smooths (the penalized "full" model can have *higher* deviance than the null, yielding a negative, untestable chi-square), and it conflated overall-level with trajectory-shape differences. Switched to the mgcv-canonical **ordered-factor difference smooth** (Wood 2017): `expr ~ s(score) + s(score, by = cond_ord) + cond_ord + <rand eff>` with `condition` as an ordered factor (WT = reference). This is a single REML fit (also ~1.4× faster than the prior three-fit LRT) and yields two interpretable, never-`NA` p-values per gene: **`p_shape`** (the `s(score):cond_ord` deviation smooth — does the WT→DKO *trajectory shape* differ, the trajectory question) and **`p_level`** (the `cond_ord` parametric offset — overall up/down shift, already covered by bulk DE). The per-gene CSV (`gam_condition_test_<model>.csv`) now has `gene,p_shape,p_level`, sorted by `p_shape`; GAM curve subtitles show both. Applied to all three GAM specs (`pseudobulk`/`fs`/`ranef`). For CD8+ T the top trajectory-shape hits are Grem1, Cd274, Irf1, Cd3e, Prf1, Il2rb, Cxcl10, Ctla4, Fasl, Pdcd1 — checkpoint/cytotoxicity/IFN programs whose spatial gradient reshapes in DKO.
- `code/R/15_04_tumor_trajectory_working.R`: Lowered the default `KDE_BW_SCALE` from `2.0` to `1.0` — at `2.0` the tumor-density field was over-smoothed, producing unrealistic per-sample score distributions for the DKO samples (a broad plateau plus an artifactual sharp spike near score≈0.45 in DKO3/DKO4). At `1.0` (the raw `bandwidth.nrd` rule-of-thumb) every sample shows the expected right-skewed decay (most cells at the periphery, fewer deep inside tumor). Also set `TOP_N_GENES` to `100` and confirmed `GAM_MODELS <- c("pseudobulk")` for the current CD8+ T analysis.
