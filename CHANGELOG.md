## 2026-09-16

### Changed
- `code/R/16_04_loso_influence.R`: The **FULL-fit baseline now uses `MIN_SAMPLES_PER_COND_PER_BIN + 1` (= 2)** for the common-support rule, matching `15_04` exactly so the baseline **is** the reported gene set (we test robustness of the actual claim, not of a looser baseline never reported). Implemented by threading a `min_samp` argument through `fit_nbfs()`/`fit_all_genes()`; the full fit passes `MIN_SAMPLES_FULL`. The **LOSO drops now FREEZE the full model's binning** (toggle `LOSO_INHERIT_FULL_BINS`, default `TRUE`): each drop inherits BOTH (a) the full model's quantile cutoffs (`build_pb()` gained an optional `breaks` arg and returns its edges; drops reuse them via `cut()` so a cell lands in the same bin regardless of which mouse is dropped) AND (b) the full model's **set of common-support-passing bins** (`allowed_bins`, computed by the new `passing_bins()` helper at `min=2`; `fit_nbfs()`/`fit_all_genes()`/`pb_report()` gained an `allowed_bins` argument that restricts a drop to those bins instead of re-evaluating common support). So a drop only removes the dropped mouse's cells from the frozen bins and refits — **a bin can LEAVE a drop (its cells fell below `MIN_CELLS_PER_BIN` = genuine influence) but never ENTER one**. This corrects an earlier (wrong) "safe by monotonicity" rationale: re-running common support at a looser `min=1` in the drops would let a single-sample-dominated bin the `min=2` baseline excluded (e.g. a DKO2-only tumor-core bin) suddenly qualify and ENTER a drop of some *other* mouse — both changing the support region and reintroducing single-mouse pseudoreplication tied to the leverage mouse. Freezing also sidesteps the old "dropping a WT mouse collapses `min=2` support" worry, since the rule is never re-applied to reduced data. `MIN_SAMPLES_PER_COND_PER_BIN` (= 1) is now only the fallback used when `LOSO_INHERIT_FULL_BINS = FALSE` (recompute edges AND re-run support per drop). No change to `16_03` (permutation still uses 1 throughout, since some of the 35 relabelings reduce an arm). Added **extensive per-model bin reporting** via a new `pb_report()` helper: for every model (full + each LOSO drop) it records one row per pseudobulk group (sample × bin) with `n_cells`, `libsize`, bin edges (`bin_lo`/`bin_hi`), `bin_score_mean`, condition label, and `bin_common_support` (whether that bin entered the GAM), plus per-model totals (`n_samples_in_model`, `n_bins_defined`, `n_pb_points_in_model`/`_analyzed`, `n_cells_in_model`/`_analyzed`) repeated per row. All models are dumped to one granular CSV `model_bin_report.csv`; a compact one-row-per-model rollup (`model_bin_summary.csv`, also printed to console) is written alongside. Also added a **`per_model_pvalues/` subdirectory** dumping the raw per-gene statistics for every model: `pvalues_full.csv` and `pvalues_drop_<sample>.csv` (each with `gene, F_shape, p_shape, z_level, p_level, edf_fs, fdr_shape, fdr_level`, sorted by `p_shape`), plus a combined `pvalues_all_models_long.csv` with a `model` column.

### Added
- `code/R/16_06_cellularity_knn.R`: New **standalone, read-only sanity check** answering reviewer point #1 on `15_04` — the concern that `score_diffusion()`'s per-sample Gaussian bandwidth `sigma <- median(knn_res$nn.dist)` (`00_utils.R:169`, computed inside each sample because `compute_tumor_score()` loops per sample) is condition-confounded, since median k-NN distance is a cell-density proxy and DKO tumor burden differs from WT. Does **not** modify `15_04`, `00_utils.R`, or `compute_tumor_score()`. **Part A** tabulates per-sample cellularity (`sigma_knn` = median k-NN distance, k=30 — exactly the σ `15_04` uses), a crude bbox density, and tumor fraction, then tests each WT-vs-DKO (`wilcox.test`, with an explicit n=3v4 floor≈0.029 / underpowered caveat — read the fold-ratio and range overlap, not the p). **Part B** (the decisive test) re-scores every cell two ways using a self-contained faithful copy of the L_sym-heat + `num/den` local-fraction path, parameterized so σ is the *only* thing that varies — once with each sample's own σ (reproduces `15_04`) and once with a single global pooled σ — and correlates the results; a validation step confirms the reimplementation matches the real `compute_tumor_score()` (Spearman = 1.000000, max|Δ| = 0). **Part C** writes a plain-language verdict to `SUMMARY.txt`. **Result:** per-sample σ does **not** separate by condition (WT mean 24.31 vs DKO 23.45, fold 0.96, ranges fully overlap; the 1.37× σ spread is between-mouse, not between-condition — smallest and largest σ are both DKO), and the score is essentially invariant to the σ choice (all-cell Spearman 0.9998, CD8+ T 0.9998, worst per-sample 0.9989). So tumor **burden** differs by condition (`tumor_frac` fold 0.47) but **cellularity** does not, breaking the reviewer's confound chain — `15_04`'s scoring is defensible as-is on the bandwidth axis. Outputs → `output/R/16_06_cellularity_knn/` (per-sample + by-condition CSVs, score-invariance CSVs, σ/density/tumor-frac PDFs, per-sample-vs-global score scatter, `SUMMARY.txt`).

### Added
- `code/R/15_04_tumor_trajectory_working.R`: New optional **adaptive `N_BINS`** selection. When `ADAPTIVE_N_BINS <- TRUE`, the number of score bins is chosen **per cell type** instead of using the fixed `N_BINS`: candidate bin counts in `[ADAPTIVE_N_BINS_MIN, ADAPTIVE_N_BINS_MAX]` (defaults 5–20) are scanned and the **largest** `n` is picked for which at least `n - ADAPTIVE_BIN_TOL_K` bins are *valid* (i.e. at most `k` bins fail; `k` defaults to 2). A bin is **valid** if it would survive the common-support rule — `>= MIN_SAMPLES_PER_COND_PER_BIN` distinct samples in **both** conditions, each contributing `>= MIN_CELLS_PER_BIN` cells — exactly the bins that feed the pseudobulk GAM, so the finest binning is kept while tolerating `k` sparse (typically WT-only tumor-core) tail bins. Implemented via two helpers next to `make_bins()`: `count_valid_bins(score, sample, condition, n_bins)` (retained-bin count under the common-support criterion, independent of whether `COMMON_SUPPORT` is toggled on for the fit) and `choose_adaptive_nbins(...)` (scans `n_max→n_min`, returns the max passing `n`, falls back to `n_min` with a warning if none qualify, and attaches the full scan table). Selection runs at the top of each cell-type iteration on that type's `ct_score`/`ct_sample`/`ct_condition`, reassigns the module-level `N_BINS` so every downstream `make_bins()`/`make_pseudobulk()`/diagnostic call in the iteration uses it, and logs the chosen `n` + full scan to `<celltype>/adaptive_nbins_scan.csv`. Default `ADAPTIVE_N_BINS <- FALSE` reproduces the current fixed-`N_BINS` behavior exactly (the fixed value remains the parameter report's nominal entry, now annotated when adaptive is on). New `stopifnot` guards (`ADAPTIVE_N_BINS_MIN >= 2`, `MAX >= MIN`, `K >= 0`) and the adaptive params added to the run-parameter report's `binning_support` group. Selection logic verified standalone on synthetic 3-WT/4-DKO data: with DKO capped at low proximity (WT-only upper bins) it correctly picks the max `n` with `#valid >= n-k` (e.g. 10, where n=11 fails).
- `code/R/17_03_functional_inspection.R`: New **GSEA functional inspection** of a tumor-trajectory condition-test gene list. ## 2026-09-14

### Added
- `code/R/15_04_tumor_trajectory_working.R`: New parameter **`FS_M`** (default 2) — the **penalty order** of the per-sample factor smooth `s(score, sample, bs="fs", k=FS_K, m=FS_M)`, exposed as a toggle for every fs spec (`pseudobulk_fs`, `pseudobulk_nb_fs`, single-cell `fs`). This implements the reviewer's suggested alternative to clamping `FS_K` for the row-order-instability fix (notes.md 2026-09-10): rather than reducing the number of per-sample basis functions (`FS_K=3`, curvature penalty), one can keep fine resolution (`FS_K=5`) but lower the penalty order to `FS_M=1`, which penalizes the 1st derivative (slope) instead of the 2nd (curvature) — pulling each per-sample curve toward a flat constant (null space {1} vs {1, x}) and shrinking per-mouse effective parameters enough to make the 63-point fit order-stable. Both configs were validated stable and give (legitimately) different hit lists. Wired through `fit_trajectory_gam(..., fs_m = FS_M)`, the three fs formula terms, the run-parameter report, and a `stopifnot(FS_M >= 1, FS_K > FS_M)` guard (1-D marginal smooth needs m≥1 and k>m). Default `FS_M=2` reproduces the current fit exactly (no behavior change); set `FS_K=5, FS_M=1` to run the reviewer's variant. Functionally verified on synthetic pseudobulk: both `m=2`/`k=3` and `m=1`/`k=5` converge and extract `p_shape`.
- `code/R/16_05_rank_based_comparison.R`: New **significant-gene-count report** alongside the existing rank-concordance analysis — where concordance asks whether setups agree on gene *order*, this asks how many hits each setup produces. For every setup (experiment × GAM model) and each test (shape / level), counts the genes clearing BH-FDR < each of `SIG_CUTOFFS` (0.05, 0.1, 0.25). Uses each run's own `fdr_shape`/`fdr_level` columns (BH over that setup's tested-gene set, so the denominator `m` is the setup's own), falling back to recomputing BH from the p-columns for older CSVs lacking `fdr_*`. Outputs: `significant_gene_counts_long.csv` (setup, exp, model, test, cutoff, n_tested, n_sig, frac_sig), `significant_gene_counts_wide.csv` (one row per setup, `<test>_fdr<cutoff>` count columns + n_tested), and `significant_gene_counts_heatmap.pdf` (setups × test-cutoff count heatmap, split into shape/level blocks, counts printed per cell, model + GAM_K row annotations matching the concordance heatmaps). The wide table also prints to console.

## 2026-09-10

### Added
- `code/R/15_04_tumor_trajectory_working.R`: New GAM spec **`pseudobulk_rs`** (random intercept + random slope), added alongside `pseudobulk` and `pseudobulk_fs` in the default `GAM_MODELS` (and `FULL_GENE_MODELS`) so the three run side-by-side, each producing its own `gam_condition_test_<model>.csv` + significant-trajectory heatmap. Responds to reviewer feedback that the per-sample factor smooth `s(score,sample,bs="fs")` is over-parameterized at 7 samples / ~9 pseudobulk points per mouse (the source of the row-order instability that forced the `FS_K<-3` clamp). `pseudobulk_rs` replaces the per-sample penalized curve with two variance components — `s(sample,bs="re")` (random intercept) + `s(score,sample,bs="re")` (random linear slope) — which is well-conditioned with no basis to saturate, hence order-stable by construction and needing **no** `FS_K`. It still holds between-mouse level + linear-trend heterogeneity in the error term (only unidentifiable non-linear per-mouse shape is given up). Fit with `select=TRUE` (Marra & Wood 2011 double penalty, so the ordered-factor difference smooth can shrink to exactly zero — removes the unpenalized-linear boundary that makes the by-smooth p-value anticonservative) and `gamma=1.4` (biases toward smoother fits), both exposed as toggleable params `RS_SELECT`/`RS_GAMMA`. Wired through `fit_trajectory_gam()` (new branch, both random terms excluded from the population-curve prediction, `select`/`gamma` now passed to `gam()` and defaulting to `FALSE`/`1` for the other specs so their behavior is unchanged), a shared `PSEUDOBULK_MODELS` vector replacing the hard-coded `c("pseudobulk","pseudobulk_fs")` model-set checks, the parameter report, and the `stopifnot` validation.
